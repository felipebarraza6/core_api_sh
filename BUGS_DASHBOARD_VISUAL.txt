┌─ BUG #1: N+1 QUERIES (LÍNEA 162-215, 335-341, 378-380, 639-648) ──────────┐
│                                                                              │
│  🔴 SEVERIDAD: CRÍTICA                 ⏱️  IMPACTO: Dashboard tarda 20-30s │
│                                                                              │
│  EL PROBLEMA:                                                              │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │ for point in obras_points_list:        # 100 puntos                 │  │
│  │     last_record = InteractionDetail    # QUERY #1                   │  │
│  │         .objects                       # QUERY #2                   │  │
│  │         .filter(catchment_point=point) # QUERY #3                   │  │
│  │         .order_by()                    # QUERY #4                   │  │
│  │         .first()                       # QUERY #5 x 100 = 500!!! │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                              │
│  EFECTO:  100 puntos = 100 queries (debería ser 1-2 queries)               │
│           1000 puntos = 1000 queries (crash garantizado)                   │
│                                                                              │
│  SOLUCIÓN: Usar Subquery/Prefetch para obtener todos en 1 query            │
│  TIEMPO FIX: 30 minutos                                                    │
│  BENEFICIO: Dashboard de 20s → 1s (20x más rápido)                         │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ BUG #5: POTENCIAL INDEXERROR (LÍNEA 734) ────────────────────────────────┐
│ Si punto no tiene variables configuradas, acceso a índice puede fallar     │
│ Solución: Verificar que variable_types no esté vacío antes de usar         │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ BUG #6: PREFETCH INCOMPLETO (LÍNEA 674-681) ──────────────────────────────┐
│ Prefetch solo selectiona ['d3', 'd6'] pero código usa ['d1', 'd3', 'd5', 'd6']│
│ Resultado: N+1 queries adicionales por cada acceso a d1 o d5               │
│ Solución: Agregar todos los campos al Prefetch.only()                      │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ BUG #7: CAST SEGURO SIN DISTINCIÓN (LÍNEA 773) ────────────────────────────┐
│ safe_float() retorna 0 para error Y para valor válido = 0                  │
│ Punto con 0.5 L/s de caudal autorizado se muestra como "no autorizado"    │
│ Solución: Modificar safe_float() para retornar (valor, es_válido)          │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ BUG #8: LOGGER REDECLARADO (LÍNEA 625, 930) ──────────────────────────────┐
│ Logger se declara múltiples veces dentro de función                        │
│ Posible memory leak en requests con crashes                                │
│ Solución: Declarar logger globalmente una sola vez                         │
└──────────────────────────────────────────────────────────────────────────────┘

┌─ BUG #9: TIMESTAMP INCONSISTENTE (LÍNEA 707) ──────────────────────────────┐
│ Si registro no tiene date_time_medition, usa timezone.now() para ordenar   │
│ timezone.now() es diferente en cada request → orden aleatorio              │
│ Solución: Usar valor fijo o default timestamp                              │
└──────────────────────────────────────────────────────────────────────────────┘
