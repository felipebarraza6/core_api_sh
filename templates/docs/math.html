El Lenguaje de las Máquinas

El álgebra lineal como lenguaje base del procesamiento de datos hidrológicos.

📐 De los números a los espacios

Un dato de telemetría hidrológica no es un número aislado. Cuando un sensor envía caudal, nivel y total cada 5 minutos, está describiendo el estado de un sistema hídrico en un instante particular. Ese estado vive en un espacio matemático concreto.

Cualquier dato cuantitativo puede representarse como un elemento de un espacio vectorial. En este motor, cada punto de captación genera una serie temporal de caudal, nivel y volumen acumulado. Estas tres magnitudes, medidas en instantes discretos de tiempo, conforman objetos matemáticos que viven en espacios de dimensión finita.

Según Strang, el álgebra lineal es el estudio de espacios vectoriales y las transformaciones lineales entre ellos. En hidrología computacional, cada eje representa una variable física medible, y cada vector representa el estado de un sistema hídrico en un instante dado. Esta no es teoría abstracta: es la base sobre la que construimos todo, desde la detección de anomalías hasta el chatbot.

Strang, G. (2016). Introduction to Linear Algebra (5th ed.). Wellesley-Cambridge Press. ISBN 978-0980232776.

Definición: Espacio Vectorial Real

Un espacio vectorial V sobre el campo R es un conjunto con dos operaciones — adición y multiplicación escalar — que satisfacen ocho axiomas de cerradura, asociatividad, conmutatividad, elemento neutro, inverso aditivo, y distributividad. Todo dato hidrológico multivariable pertenece intrínsecamente a algún V = Rn.

Vectores: Series Temporales como Trayectorias

Comparar dos días de operación con 288 mediciones cada uno requiere una representación vectorial.

🌊 El caudal como vector

Una gráfica de caudal vs tiempo funciona para visualizar un día, pero comparar dos días distintos requiere una estructura matemática diferente. La representación vectorial permite operaciones como distancia, correlación y proyección que no son posibles en una visualización bidimensional.

Supongamos un punto de captación que reporta caudal cada 5 minutos. En una hora tenemos 12 mediciones. Si concatenamos las mediciones de un día completo (288 muestras), obtenemos un vector:

x = [x1, x2, ..., x288]T ∈ R288
x Vector de mediciones de una variable en un día completo. Dimensión 288 (una muestra cada 5 minutos). Tipo: real.
xi i-ésima medición del vector. Tipo: real. Ej: caudal en el i-ésimo intervalo de 5 minutos.
R288 Espacio vectorial de 288 dimensiones sobre los números reales.
R Conjunto de números reales. Rn denota un espacio vectorial de n dimensiones sobre R.

Cada componente xi es un número real (litros por segundo). El espacio R288 es enorme, pero la física del problema impone restricciones: los caudales no pueden ser negativos, y la variación entre muestras consecutivas está acotada por la inercia hidráulica del sistema. Esto significa que los vectores de caudal no llenan todo el espacio; viven en una variedad (manifold) de dimensión mucho menor.

📏 Distancia y similitud entre patrones

Para comparar dos días de operación necesitamos una métrica en el espacio vectorial. La más natural es la distancia euclidiana:

d(x, y) = ||x - y||2 = √(Σi=1n (xi - yi)2)
d(x, y) Distancia euclidiana entre dos vectores x e y. Mide qué tan "diferentes" son dos días de operación.
||·||2 Norma euclidiana (o norma L2). Raíz cuadrada de la suma de cuadrados de las componentes.
Σ Sumatoria. Σi=1n indica sumar desde i=1 hasta i=n.
n Dimensión del vector. Número de componentes. Ej: n=288 para un día de muestras cada 5 minutos.
y Segundo vector de mediciones (ej: otro día de caudal para comparar con x). Misma dimensión que x.
yi i-ésima componente del vector y. Tipo: real.

Sin embargo, la distancia euclidiana ignora la correlación temporal: dos días con el mismo patrón pero desplazados una hora aparecerían como muy diferentes. Desde el punto de vista algebraico, la correlación no es más que el coseno del ángulo entre vectores centrados:

corr(x, y) = cos(θ) = (xTy) / (||x|| · ||y||)
corr(x, y) Correlación entre dos vectores. Equivalente al coseno del ángulo entre vectores centrados. Rango: [-1, 1].
θ Ángulo entre los vectores x e y en el espacio Rn. θ=0 → vectores paralelos (máxima correlación).
||x|| Norma euclidiana (longitud) del vector x. ||x|| = √(x₁² + x₂² + ... + xₙ²).
xTy Producto punto (o producto interno) entre x e y. Suma de productos componente a componente: Σ xᵢyᵢ.
Dos vectores en R²: y ↑ | ★ y (día anómalo) | /| | / | d(x,y) = ||x-y|| | / | |/ | ●────┼────→ x x | | θ = ángulo entre vectores cos(θ) alto = patrones similares

Matrices: Sistemas Multivariables

Tres variables correlacionadas (caudal, nivel, total) que no pueden analizarse por separado.

🔄 De vector a matriz

La telemetría completa reporta tres variables simultáneas que evolucionan juntas. El caudal sube cuando baja el nivel. El total acumulado crece en proporción. No pueden analizarse por separado. Esa correlación forzada es lo que hace que los datos hidrológicos vivan en una estructura matricial.

Un pozo con telemetría completa reporta tres variables cada 5 minutos. Si organizamos un día de datos como filas (tiempo) y columnas (variables), obtenemos una matriz X ∈ R288×3:

X = [ [q1, n1, t1], [q2, n2, t2], ..., [q288, n288, t288] ] -- q = caudal (L/s), n = nivel (m), t = total (m³)
X Matriz de datos. Filas = instantes de tiempo, columnas = variables (caudal, nivel, total).
qi Caudal en el i-ésimo instante. Unidad: litros por segundo (L/s). Tipo: real.
ni Nivel en el i-ésimo instante. Unidad: metros (m). Tipo: real.
ti Total acumulado en el i-ésimo instante. Unidad: metros cúbicos (m³). Tipo: real.

🔎 SVD: Descomposición en Valores Singulares

La SVD descompone cualquier matriz de datos X en tres matrices que revelan la estructura interna del sistema hidrológico:

X = U Σ VT
X Matriz de datos original. Filas = tiempo, columnas = variables (caudal, nivel, total).
U Modos temporales. Cada columna es un patrón de comportamiento en el tiempo (ej: ciclo diario).
Σ Valores singulares σ₁, σ₂, σ₃. Indican qué tan "importante" es cada modo. σ₁ ≥ σ₂ ≥ σ₃ ≥ 0.
Vᵀ Combinaciones de variables. Indica cómo se mezclan caudal, nivel y total en cada modo.
SVD como descomposición: ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │ │ σ₁ 0 0 │ │ │ │ U │ × │ 0 σ₂ 0 │ × │ Vᵀ │ │ │ │ 0 0 σ₃│ │ │ └─────────┘ └─────────┘ └─────────┘ ↑ ↑ ↑ modos importancia combinaciones temporales de cada modo de variables σ₁ >> σ₂ ≈ σ₃ → 1 modo domina σ₁ ≈ σ₂ ≈ σ₃ → 3 modos independientes

Valores singulares de un pozo real:

σ₁ domina: caudal, nivel y total están acoplados. Un solo modo explica el 85% de la varianza.

En hidrología, la SVD revela modos dominantes de comportamiento. El primer valor singular σ₁ captura la tendencia principal (ej: ciclo diario de riego). Si σ₂/σ₁ ≈ 0, el sistema es esencialmente unidimensional. La SVD también permite compresión y denoising: reconstruir X usando solo los k valores singulares más grandes filtra ruido de medición.

Golub, G. H., & Van Loan, C. F. (2013). Matrix Computations (4th ed.). Johns Hopkins University Press. ISBN 978-1421407944.

📉 PCA: Proyección en subespacios principales

PCA encuentra las direcciones donde los datos varían más. Es la SVD aplicada a la matriz centrada. Proyecta los datos a un espacio más pequeño conservando la información esencial:

Z = Xc W
X_c Matriz centrada: cada variable tiene media cero. Elimina sesgos de escala.
W Matriz de componentes principales. Cada columna es una dirección de máxima varianza.
Z Datos proyectados. Z tiene menos columnas que X pero conserva el 95% de la información.
PCA como proyección: n (nivel) ↑ │ · · · │ · · · · │ · · · · · │· · · · · ← nube de datos │ · · · · · (caudal vs nivel) │ · · · · · └──────────────────→ q (caudal) ↑ PC₁: dirección de máxima varianza Proyección en PC₁ = información esencial Residual perpendicular a PC₁ = anomalía potencial

Tensores: Datos en Batch y Deep Learning

La estructura matemática que permite a un modelo de lenguaje procesar conversaciones sobre telemetría hidrológica.

📦 Definición tensorial

Un modelo de lenguaje como Gemini representa una conversación como una secuencia de vectores (tokens), donde cada vector vive en un espacio de miles de dimensiones. Y no es una sola conversación: es un batch de conversaciones procesadas en paralelo. Esa estructura — batch × secuencia × dimensión — es un tensor de orden 3. Sin entender esto, es imposible dimensionar la memoria GPU o interpretar qué está haciendo el modelo.

Un tensor de orden k generaliza escalares (k=0), vectores (k=1) y matrices (k=2) a k dimensiones. En hidrología, un tensor de orden 3 emerge cuando consideramos múltiples puntos a través del tiempo:

T ∈ RP × T × V -- P: número de puntos de captación -- T: pasos temporales (ej: 288 muestras/día) -- V: variables por punto (caudal, nivel, total = 3)
T Tensor de orden 3 que generaliza la matriz a tres dimensiones. En este contexto: batch de puntos × tiempo × variables.
P Número de puntos de captación en el batch. Tipo: entero ≥ 1.
T Pasos temporales. Ej: 288 muestras en un día con frecuencia de 5 minutos. Tipo: entero.
V Número de variables medidas por punto. En este motor típicamente V = 3 (caudal, nivel, total).
k Orden del tensor (número de índices). Escalar k=0, vector k=1, matriz k=2, batch hidrológico k=3.

🧠 Embeddings: palabras como vectores

Los LLM (como Gemini, usado en el chatbot de esta API) operan en espacios vectoriales de alta dimensión. El primer paso es convertir tokens en embeddings: vectores densos en Rd donde d típicamente está entre 768 y 4096.

De palabra a vector: "caudal" ──→ [0.23, -0.81, 0.15, ..., 0.44] ∈ R^d "litros" ──→ [0.19, -0.75, 0.21, ..., 0.38] ∈ R^d "flujo" ──→ [0.25, -0.79, 0.18, ..., 0.41] ∈ R^d "perro" ──→ [-0.62, 0.33, -0.71, ..., 0.12] ∈ R^d ↑ lejos de hidrología d(caudal, litros) ≈ 0.1 ← cercanos d(caudal, perro) ≈ 1.8 ← lejanos

Relaciones semánticas lineales:

embedding("rey") - embedding("hombre") + embedding("mujer") ≈ embedding("reina")

En este motor, cuando un usuario pregunta "¿cuánto extraje ayer?", el modelo proyecta la consulta a un vector y lo compara con el espacio de intenciones posibles (medición, tendencia, alerta, ayuda).

embedding Función que mapea un token (palabra o subpalabra) a un vector denso en Rd. Los embeddings se aprenden durante el entrenamiento del modelo.
Mikolov, T., Chen, K., Corrado, G., & Dean, J. (2013). "Efficient estimation of word representations in vector space". arXiv:1301.3781.

🔷 Redes neuronales como composición de transformaciones

Mecanismo de Atención: El Corazón del LLM

Por qué el chatbot no responde con frases genéricas: la matemática que le permite conectar "caudal" con "alerta" y "DGA" en una misma conversación.

🎯 Atención como producto punto escalado

Un sistema de respuesta basado en reglas fijas asocia palabras clave con respuestas predefinidas. Si el usuario dice "caudal", responde con el último valor. Este enfoque falla cuando la pregunta requiere contexto: "¿por qué mi caudal subió después de la lluvia?" implica relacionar "lluvia" con "caudal", algo que el mecanismo de atención resuelve matemáticamente.

El mecanismo de atención determina qué tokens de una oración son relevantes entre sí. Cada token genera tres representaciones vectoriales diferentes:

Q = X WQ K = X WK V = X WV Attention(Q, K, V) = softmax(QKT / √dk) V
Q (Query) "¿Qué estoy buscando?" Representación del token que hace la pregunta.
K (Key) "¿Qué ofrezco?" Representación de cada token candidato a ser consultado.
V (Value) "¿Qué información tengo?" Contenido real que se entregará si hay match.
d_k Dimensión de los vectores Q y K. Divide para evitar valores extremos en el producto punto.
softmax Convierte puntuaciones de similitud en probabilidades que suman 1. Mayor puntuación = más atención.
WQ, WK, WV Matrices de proyección aprendibles que transforman X en Query, Key y Value respectivamente. Tipo: real.
Attention Función de atención escalada. Calcula pesos de relevancia entre todos los pares de tokens y produce un vector enriquecido.
Matriz de atención A = softmax(QKᵀ/√d): "el" "pozo" "5" "de" "Iansa" ┌────────────────────────────┐ "el" │ 0.4 0.2 0.1 0.1 0.2 │ "pozo"│ 0.1 0.5 0.2 0.1 0.1 │ "5" │ 0.1 0.2 0.4 0.1 0.2 │ ← "5" atiende a "pozo" e "Iansa" "de" │ 0.1 0.1 0.1 0.3 0.4 │ "Iansa│ 0.1 0.1 0.2 0.2 0.4 │ └────────────────────────────┘ ↑ valores más altos = más atención Cada fila suma 1 (probabilidad)

En una conversación hidrológica, si el usuario dice "el pozo 5 de Iansa", los tokens "pozo" y "5" generan queries que alinean fuertemente con la key de "Iansa" en la memoria contextual. La salida de atención enriquece la representación del token actual con información de todo el contexto previo.

Vaswani, A., et al. (2017). "Attention is all you need". Advances in Neural Information Processing Systems, 30.

🔄 Multi-head attention: atención paralela

En vez de una única proyección, los transformers aplican h atenciones en paralelo con proyecciones diferentes, concatenando los resultados:

MultiHead(Q, K, V) = Concat(head1, ..., headh) WO headi = Attention(QWiQ, KWiK, VWiV)
MultiHead Función que ejecuta h mecanismos de atención en paralelo con proyecciones diferentes, y mezcla los resultados.
Concat Operación de concatenación. Une los h vectores de salida de cada cabeza en un único vector largo.
headi Salida de la i-ésima cabeza de atención. Cada cabeza especializa en un tipo de relación diferente.
h Número de cabezas de atención en paralelo. Tipo: entero. Ej: h=8 o h=12 en transformers estándar.
WO Matriz de pesos de salida. Mezcla linealmente las h cabezas concatenadas en la representación final.
WiQ, WiK, WiV Matrices de proyección de la i-ésima cabeza. Cada cabeza tiene sus propios pesos aprendibles.
H1

Coreferencia

"el pozo" = "punto 5"

H2

Temporal

"ayer" = fecha específica

H3

Jerárquica

"Iansa" ⊃ "pozo 5"

H4

Semántica

"caudal" ≈ "litros"

Cada "cabeza" puede especializarse en un tipo de relación diferente. La composición lineal final WO mezcla estas especializaciones en una representación unificada.

Detección de Anomalías: Geometría del Error

Detectar comportamiento anómalo en un pozo sin revisar 288 datos manualmente cada día.

📐 Distancia de Mahalanobis

La detección manual de anomalías funciona para pocas fuentes, pero no escala. Una caída repentina de caudal, un nivel inconsistente o un total que se resetea son patrones identificables visualmente en 10 pozos, pero no en 100. La alternativa matemática es geométrica: los datos normales de un pozo no llenan todo el espacio; viven en una estructura de dimensión mucho menor. Lo que cae fuera de esa estructura es anómalo.

La distancia euclidiana trata todas las direcciones igual. Pero en hidrología, caudal y nivel están correlacionados: si ambos cambian juntos, es normal. Si solo uno cambia, es anómalo. Mahalanobis mide distancia respetando la forma de la nube de datos:

D2(x) = (x - μ)T Σ-1 (x - μ)
x Vector de mediciones del pozo en un instante: [caudal, nivel, total].
μ Vector de medias históricas. Es el "centro" del comportamiento normal.
Σ Matriz de covarianza. Captura cómo se correlacionan las variables entre sí.
Σ⁻¹ Inversa de covarianza. Acorta distancias en direcciones de alta correlación.
D² Distancia al cuadrado. Si D² > τ → el punto es anómalo.
D Distancia de Mahalanobis (raíz cuadrada de D²). Mide desviación respecto al comportamiento normal en unidades de desviación estándar.
Euclidiana vs Mahalanobis: nivel ↑ │ ╭────────╮ │ ╱ ·A ╲ │ │ · · │ │ │ · ● · │ ← nube normal │ │ · · │ (caudal vs nivel │ ╲ ·B ·╱ correlacionados) │ ╰────────╯ └──────────────────→ caudal Euclidiana: d(A,●) = d(B,●) Mahalanobis: D(A) >> D(B) A está en la dirección de la correlación → menos anómalo

Ejemplo concreto:

Un pico de caudal sin cambio de nivel podría tener distancia euclidiana "normal", pero Mahalanobis detecta la ruptura de correlación.

🔺 Subespacios normales y anómalos

Tras PCA, los datos normales se alinean en pocas direcciones principales. Cualquier desviación perpendicular a esas direcciones es anómala:

x = xnormal + xresidual ||xresidual||² = Σi=k+1r (uiTx)2
x Vector de observación actual (medición del pozo).
x_normal Proyección de x sobre los k componentes principales. Representa comportamiento esperado.
x_residual Lo que sobra después de proyectar. Es perpendicular al subespacio normal. Cuanto mayor, más anómalo.
u_i i-ésimo vector singular de U. Cada u_i es una dirección ortogonal en el espacio de datos.
k Número de componentes principales conservados. k=1 para un pozo donde todo está acoplado.
τ Umbral de anomalía. Se calibra con percentil 99 de datos históricos normales.
r Rango de la matriz de datos (número de valores singulares no nulos). r = min(filas, columnas) en la práctica.
||xresidual||² Norma al cuadrado del residual. Mide la magnitud de la desviación perpendicular al subespacio normal.

Este flujo matemático — vector → proyección → norma residual → umbral — es la base teórica de las heurísticas de auditoría que este motor aplica automáticamente.

Mapa Matemático del Motor

Cada componente del sistema traducido a objetos matemáticos. Las variables se definen antes de usarse.

📝 Notación común en esta sección

R = conjunto de números reales. Rn = espacio vectorial de n dimensiones. Rn×m = espacio de matrices con n filas y m columnas. Las dimensiones se escriben como (filas × columnas).

📡 Telemetría

Objeto: Matriz de lecturas X ∈ RT×V

T Número de lecturas temporales. Entero ≥ 1. Ej: 288 lecturas en un día con frecuencia de 5 minutos.
V Número de variables medidas. Entero ≥ 1. En este motor típicamente V = 3 (caudal, nivel, total).
X Matriz de datos. Cada fila es un instante de tiempo, cada columna es una variable. Tipo: real (float64).

Operaciones: Diferenciación temporal (Δtotal/Δt → caudal), interpolación lineal para huecos, validación de rangos.

Espacio concreto: R288×3 para un día de telemetría a 5 minutos con 3 variables.

⚠️ Alertas Umbral

Objeto: Función indicadora χ[a,b](x)

x Valor medido en un instante. Tipo: real (float). Ej: caudal = 15.3 L/s.
a, b Límites inferior y superior del umbral configurado. Tipo: real. a ≤ b.
χ Función indicadora. Vale 1 si x está fuera de [a,b], 0 si está dentro. Tipo: entero {0, 1}.

Operaciones: Comparación escalar (x < a o x > b), lógica booleana compuesta (AND/OR entre múltiples condiciones).

Espacio: R → {0, 1}. El dominio son los reales (valores medidos); el codominio es binario (alerta/no alerta).

🤖 Chatbot (Gemini)

Objeto: Secuencia de embeddings E ∈ Rn×d

n Número de tokens (palabras o subpalabras) en la entrada. Tipo: entero ≥ 1.
d Dimensión del vector de embedding. Tipo: entero. En Gemini, d ≈ 768 a 4096 según el modelo.
E Matriz de embeddings. Cada fila es un token convertido a un vector numérico de d dimensiones. Tipo: real.

Operaciones: Multi-head self-attention, redes feedforward, softmax sobre el vocabulario de salida.

Espacio: Rd — cada token vive en un espacio semántico latente de d dimensiones donde palabras similares están cerca.

📊 Reportes DGA/SMA

Objeto: Agregaciones temporales sobre ventanas de datos

T Número de lecturas crudas en la ventana temporal. Tipo: entero. Ej: 288 lecturas diarias a 5 min.
k Número de reportes agregados resultantes. Tipo: entero. Ej: 1 reporte diario (k=1) o 24 reportes horarios (k=24).

Operaciones: Proyección sobre ventanas (GROUP BY temporal), reducción de dimensionalidad: sumas, promedios, máximos, mínimos.

Espacio: RT → Rk. Toma T lecturas individuales y las comprime en k valores agregados.

🔍 Auditoría de Datos

Objeto: Residuo de reconstrucción ||x − x̂||

x Vector de observación actual. Dimensión d. Tipo: real. Ej: [caudal, nivel, total] en un instante.
x̂ Reconstrucción de x usando solo los k componentes principales. Tipo: real. Dimensión d.
k Número de componentes principales conservados. Tipo: entero. k < d.
d Dimensión original del vector de observación. Tipo: entero. En este motor, d = 3.

Operaciones: SVD truncada, proyección ortogonal sobre el subespacio normal, norma del residual.

Espacio: Rk ⊂ Rd. El subespacio normal tiene k dimensiones (las principales) dentro del espacio original de d dimensiones.

📈 Tendencias

Objeto: Regresión lineal y = Xβ + ε

y Vector de valores observados (ej: niveles freáticos en T instantes). Dimensión T×1. Tipo: real.
X Matriz de diseño. Primera columna = 1s (intercepto), segunda = tiempos t₁...tₜ. Dimensión T×2. Tipo: real.
β Vector de parámetros [β₀, β₁] = [intercepto, pendiente]. Dimensión 2×1. Tipo: real.
ε Vector de errores o residuos. Dimensión T×1. Tipo: real. Media teórica = 0.

Operaciones: Estimación por mínimos cuadrados β̂ = (XTX)−1XTy, cálculo del error cuadrático medio.

Espacio: R2 — el parámetro β vive en un plano bidimensional: eje horizontal = intercepto, eje vertical = pendiente.
